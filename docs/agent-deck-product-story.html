为什么是现在

The shift

不缺更多对话框，
缺的是工作系统。

当 AI 可以同时推进很多任务，新的瓶颈变成了人的注意力：怎样保持上下文清晰、知道何时介入，并确认“完成”真的发生了。

01 · CONTEXT

会话越多，背景越容易碎

窗口切换、重复说明和全量历史广播，让重要约束被噪音淹没，也让 Token 持续膨胀。

02 · CONTROL

Agent 很忙，人却更焦虑

没有依赖、回执和明确的下一步，人只能守着多个终端，猜测任务在哪里、为什么卡住。

03 · VALUE

成本可见，价值却不可见

我们知道消耗了多少 Token，却常常说不清结果是否被采用、节省了多少时间、降低了什么风险。

One complete loop

从一句目标，
到一个可验收的交付。

Agent Deck 用最轻的执行拓扑完成任务，把人放在真正需要判断的位置，把每一次完成落到证据与产物上。

1写下目标结果、完成标准、工作区与执行预算
2自适应路由简单任务 Direct，复杂任务 Mission
3真实执行真实会话、工作区与 Worktree
4最小上下文只共享已验证事实、依赖与证据
5关键决策计划、阻塞、评审和集成时介入
6价值闭环产物、证据、成本与采用结果
Core capabilities

不是更多 Agent，
而是更少失控。

统一控制面管理会话、编排、上下文、注意力、证据和价值，同时保留每个 Provider 的真实执行能力。

Adaptive Runtime

让编排成本必须物有所值

边界清晰的工作保留一个连续上下文；只有存在真实并行收益的任务才进入 Planner、DAG 与多 Worker。

  • Direct：0 Planner + 1 Worker
  • 依赖安全的 Mission DAG
  • 用户可显式覆盖路由
Context Kernel

共享得紧密，但不臃肿

按任务装配目标、约束、已验证事实、依赖产物和证据引用，不把完整聊天复制给所有 Agent。

  • 预算化上下文胶囊
  • 结论可回溯到原始证据
  • 面向轨迹检索持续演进
Attention OS

注意力可以有不同范式

同一份真实状态可以变成单一决策队列、全局控制室或一页简报，适配不同角色和工作时刻。

  • Focus Queue / Control Room
  • Briefing 与显式延后
  • 推进、交付、风险、价值四种排序
Evidence & Usage

完成必须有证据，执行必须可复核

文件、Diff、测试、命令、来源和 HTML 交付物共同构成验收依据；运行记录和 Token 用量明确区分实测与估算。

  • 真实进度，不用 Mock 冒充完成
  • HTML-first 交付与原始附件
  • Provider Token 真值与执行预算

Engineering truth

我们如何看待
速度与质量。

Agent Deck 不回避多 Agent 的成本，也不以 Agent 数量替代有效产出。

首轮三个同题、同模型、同推理档位的简单任务配对实验中，双方均通过全部隐藏检查，Agent Deck Direct 与直接 Codex 的平均耗时接近持平。重复实验存在明显方差，因此这是早期工程证据，不是稳定领先结论。我们的标准是：简单任务不因编排显著退化，复杂任务必须在质量、注意力成本或交付完整度上给出可验证收益。
