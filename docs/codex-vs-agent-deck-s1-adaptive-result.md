# S1 自适应 Runtime 同题复测

## 结论

新版 Agent Deck 已消除旧多 Agent 方案的主要负收益，并在同一 S1 隐藏测试上追回直接 Codex 的确定性质量；但速度仍未达到基线，当前不能宣称整体超过 Codex。

| 指标 | 直接 Codex 基线 | 旧 Agent Deck | 新 Agent Deck Direct |
| --- | ---: | ---: | ---: |
| `T_green` | 69.3s | 1315.6s（首次声称完成；隐藏测试失败） | 188.3s |
| 公开测试 | 5/5 | 5/5 | 8/8 |
| 隐藏测试 | 7/7 | 6/7 | 7/7 |
| Planner | 0 | 1 | 0 |
| Worker | 1 | 4 | 1 |
| 人工触点 | 0 | 9 | 1 |
| 结果 | 通过 | 隐藏测试失败 | 通过 |

新版相对旧版：

- 墙钟时间下降约 85.7%。
- Worker 数量下降 75%。
- 人工触点下降 88.9%。
- 隐藏检查从 6/7 恢复为 7/7。

新版相对直接 Codex：

- 确定性检查同为全通过。
- 仍慢 119.0 秒，约为基线的 2.72 倍。
- 多一次结果验收；这是当前产品保留的安全门。
- 新版记录的 1,032 Token 是本地估算，而基线 147,975 是 Provider 口径，二者不能直接比较。

## 这轮具体改变

1. 本地确定性路由选择 Direct：0 Planner、1 Worker、1 Worktree。
2. Direct 不再注册跨 Agent 消息总线工具，也不再注入 Mission 扩展字段、共享上下文和产物协议长模板。
3. Direct Prompt 只保留任务、验收、最小行为分区和验证要求。
4. 对 parser/validator/CLI 类任务要求覆盖标准有效值、边界有效值、近似非法值、类型、标准化和公共 API 兼容性。
5. 一次人工验收后自动提交和集成。

## 失败也保留为证据

第一轮 Direct 在 226.7 秒后公开测试通过，但隐藏测试只通过 6/7，遗漏首尾空白输入。第二轮加入较长的行为分区指令后运行超过 10 分钟，被评测器判定超时。第三轮改为精简直通 Prompt 后在 188.3 秒通过全部检查。

这些结果说明：增加 Agent 数并不能自动提高质量，继续堆长 Prompt 也会恶化延迟。下一阶段应把可确定的预检、测试选择和反例生成移入本地 Runtime，同时测量模型回合与工具批次，而不是再增加协调层。

## 可复现方式

```bash
npm run eval:s1:adaptive
```

执行器每次从固定 seed commit 创建隔离克隆，启动真实 Agent Deck Direct Mission，完成后独立运行公开与隐藏 grader，并把原始测试输出、Diff、路由、时间、Worker 和 Token 口径写入 `../evals/results/s1-adaptive-*.json`。
