AGENT DECK · 执行方式

你给目标，主 Agent 检查并推进。

可选的自主执行模式，把常规审批、结果验收和成果集成交给主 Agent。它检查真实文件与执行证据，而不是直接相信 Worker 的“已完成”。

怎么开启

打开 设置 → 如何推进新工作 → 自主执行，确认一次完整工具权限提示。然后在「工作」里启动事项。仅保存笔记不会触发执行；已有工作保持原模式。

完整工具权限不是安全沙箱。执行 Agent 可以运行任意 Bash、写文件、联网或安装依赖，可能影响工作区外的数据。只对可信任务开启；OS 授权、组织限制、账号登录与验证码不会被绕过。自检也不是正确性保证。

从启动到交付

01 · 启动准备计划

只读检查环境，提出工作区策略；按自主策略批准。

02 · 执行依赖安全的 DAG

独立任务并行；有依赖的任务等前置通过自检。

03 · 核验主 Agent 自检

独立只读上下文，low 思考；核对每条完成标准和实际证据。

04 · 修正有限重试

不通过就给原 Worker 明确反馈，最多自动修正两次。

05 · 汇总最终独立核验

自动合并；冲突交给主 Agent 修正。再只读检查集成成果。

轻自检，不重复整个任务

独立，但上下文精简

只带原始目标、完成标准、简要证据和当前工作区，不复制完整多 Agent 对话。自检禁止写入、委派和公开发布。

有明确预算

每次自检使用 low 思考强度、两分钟时间预算，并要求最多三批聚焦检查。自有 Harness 还限制工具轮次与已报告 Token；兼容 API 未声明 low 能力时，不发送不支持的参数。

这里减少的是检查开销与人工等待；模型服务排队、复杂测试和网络速度仍可能很慢。没有承诺固定加速比或优于单会话基线。

两种引擎，同一个推进方式

路径执行权限自检
外部 CodexWorker 使用 danger-full-access 与 approvalPolicy: never。所连接的组织策略仍可能拒绝。独立 read-only Thread，禁用委派、MCP、Hooks 和网页访问；low effort。
Agent Deck Harness工具代理按任务预授权，Bash 不再限于手工批准的命令集合；保留格式、路径和执行超时检查。只读工具、结构化证据检查、独立线程。避免自检内部再嵌套一轮模型审计。
Claude Code / Trae完整生命周期适配仍未开放。这个开关不会把未验证的适配器变成可执行引擎。

你仍然看得清，也停得下

  • 核验记录带模型、真实工具回执、检查结果与低思考参数；成果标为 agent_verified，不冒充用户验收。
  • 缺证据、检查失败、超时或额度/登录问题不会被伪装成成功。修正耗尽后进入明确的阻塞状态。
  • 停止任务先关闭推进门；迟到结果不能继续验收。重启接回已持久化的自检，遇到不确定写操作不会自动重放。
  • 自主推进只负责任务范围内的执行与集成，不额外授权无关购买、公开发布或读取私人资料。

怎么验证这项能力

npm run test:autonomous 覆盖默认人工模式、权限传递、依赖推进、自检失败、有限修正、取消竞态、恢复与冲突集成。npm run test:autonomous:live 使用独立临时仓库做实际模型小任务，不修改生产偏好或账本。

2026-10-08，实际 Codex gpt-5.5 文件任务已完成：节点和最终成果各一次 low 自检，均有真实工具回执，人工授权等待为 0。这是一个小任务的可用性证明，不是质量或速度基准。自有 API 路径目前由协议与工具代理测试覆盖，不代表已做真实 DeepSeek 全流程评测。
