# Agent Deck V0.4 — Adaptive Attention Foundation

V0.4 starts the product’s attention operating system without changing the execution truth source: Codex Threads, Mission state, task dependencies, artifacts, and user actions remain local and durable. The new layer only projects that truth into different ways of steering work.

## What ships in the foundation

| Capability | Behavior | Truth source |
| --- | --- | --- |
| Attention object | Each pending decision has a deterministic priority, reason, downstream impact, confidence, and recommendation. | Mission and task state in SQLite |
| Focus Queue | Presents one highest-priority decision, an explanation of why it is now, and a real defer action. | `attention_state` plus active Mission state |
| Control Room | Keeps the cross-Mission queue for users who prefer scanning and comparing work. | Same attention projection |
| Briefing | Summarizes the latest 24 hours: open decisions, active workers, verified tasks, artifacts, and changed Missions. | Local Mission ledger |
| Deferral | A user may delay an active decision by 15m, 1h, 4h, or one day. It returns automatically; it is never marked resolved. | `attention_state.deferred_until` |
| Priority modes | The same decision ledger can be ordered for flow, delivery, or risk. The selection is a local UI preference; it never changes Mission state or approves work. | Operational priority + dependency impact |

## Priority is explainable

Priority is a deterministic local projection, not an LLM judgement. Base urgency comes from the operational state (for example, a blocked worker is higher than a review). A task’s dependency graph adds up to 16 points based on the number of downstream tasks it prevents. The UI marks these values as derived and shows the corresponding `Why now` factors.

This protects the user from fabricated urgency while allowing explicit preference-aware ordering. The UI exposes the operational baseline, preference adjustment, and reason on every affected decision.

## The product model

```text
Codex / providers ──> Mission ledger ──> Attention policy ──> Focus | Control | Briefing
                           │                    │
                           └── artifacts, runs, dependencies ──> explainable priority
```

The V0.4 policy is deliberately conservative. It does not infer a person’s preferred focus style, auto-approve work, or manufacture a summary. Users select their mode explicitly; later releases can add schedules, interruption budgets, and learning from explicit user choices on top of the same durable object.

## Validation

- Mission-core tests verify priority calculation, dependency impact, persisted deferrals, and ledger-backed briefing counts.
- Attention-policy tests verify that profile ordering is deterministic and never mutates the durable operational priority.
- The desktop app receives data through the existing Electron IPC bridge and updates from the existing Mission update stream.
- Existing review, artifact, and worktree gates remain unchanged.
