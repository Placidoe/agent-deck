不只是开一轮对话，而是接着推进自己的事

我把这一步聚焦在长期项目、用户掌握的记忆和低成本恢复上。工作、审批、成果仍然使用同一份真实账本；两种执行模式继续保留。它是 Personal Agent 的基础，不是已经能包办生活的全能助手。

怎么用

  1. 进入工作 → 项目与记忆，创建项目，写清长期目标。项目名称、目标和已验收结果可用于后续模型请求。
  2. 点击记住一件事。默认只在本机保存，勾选“允许用于 Agent 请求”才会主动提供给配置的模型服务。个人偏好作用于全部项目，项目记忆只作用于所属项目。
  3. 新建工作时选择所属项目；已有工作也可在详情关联项目。运行中或待批准的执行不能中途换项目。
  4. 重新打开项目，查看上次做到哪了。它直接读取账本，展示真实状态、验收数、异常和下一步；不会调用模型或重新启动任务。
  5. 展开检查下一次请求的背景，查看可复用记录、来源、字符预算。真正发送时还会按任务词排序，并排除当前 Mission。

架构与职责

桌面工作台：工作 / 待我处理 / 成果

项目与记忆是“工作”里的辅助视图，不增加第四个主入口。一个项目包含多次工作，每次工作仍拥有自己的执行记录。

PersonalStore · 同一份 SQLite

项目目标、作用范围、来源、有效期、分享授权、版本号。关联 Requirement 与 Mission，但不创建重复任务。

恢复视图 · 本地状态投影

任务账本 → 待批准 / 阻塞 / 待验收 / 完成 → 明确的下一步。只读取，不产生模型开销。

请求前筛选 · 可追溯背景快照 ↓

已确认 + 允许分享 + 未过期 → 项目同名记忆覆盖个人偏好 → 当前项目的已验收摘要 → 任务词排序 → 默认 6,000 字符 / 最多 20 条。记录 ID、版本和数量进入事件账本，不重复存全文。

外部 Agent + 轻量 Harness

主 Agent、Worker 和后续消息都获得当前背景快照；外部 Agent 负责自己的推理与工具循环。

Agent Deck Harness SDK

产品提供目标与当前背景；独立 SDK 负责 Manager / Executor / Auditor 和受控工具。SDK 不依赖个人项目的 SQLite 结构。

边界必须说清楚

“允许分享”是向模型服务提供背景的授权，不是执行任何操作的授权。记忆中的内容属于引用数据；不能绕过工具批准、文件隔离或人工验收。

修改、过期和撤销会影响后续主动注入的快照，但不会抹除以前发送的提示词、外部 Agent 历史或已保存的运行记录。当前执行中的模型请求也不会被悄悄重写。

目前是有范围和预算的词匹配排序，不是语义检索，也不保证上下文完全无噪音。恢复读取最近 20 次执行和最多 12 项待处理记录；记忆界面读取最近 300 条。未验收的模型结论不会自动变成事实。

验证与未完成事项

87 项回归与 4 项网站交付测试通过；源码版和实际打包版均通过 Electron 操作流程，以及 1540×960 / 1120×720 布局检查。桌面测试使用明确标注的临时 QA 项目，不访问真实用户资料、不发送真实模型请求。它验证生命周期、权限边界和使用流程，不能证明真实模型质量或相对 Codex 的速度收益。

无可复用背景的普通任务不增加个人上下文提示词；撤销此前已注入的记忆时发送必要的替换快照。当前桌面包仅供本机 Beta 体验，尚未签名和公证，不是正式市场发行版。
